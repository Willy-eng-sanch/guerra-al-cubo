# Política de seguridad

## Reportar una vulnerabilidad

No publiques vulnerabilidades explotables, credenciales, tokens ni datos personales en Issues públicos.

Hasta que se publique un contacto privado dedicado, utiliza la función **Report a vulnerability** de GitHub Security Advisories del repositorio, si está habilitada. Si no está disponible, contacta al mantenedor por un canal privado oficial y comparte únicamente la información necesaria.

## Qué incluir

- componente y versión/commit afectados;
- impacto potencial;
- pasos de reproducción seguros;
- prueba de concepto mínima, sin afectar servicios o datos ajenos;
- mitigación sugerida, si existe.

## Alcance

Se consideran relevantes vulnerabilidades en el cliente, dependencias, persistencia local, importación/exportación de archivos, lobby y cualquier servicio futuro.

No realices pruebas contra cuentas, dispositivos o infraestructura de otras personas sin autorización.

## Gestión

El mantenedor confirmará recepción, evaluará impacto, coordinará una corrección y decidirá cuándo publicar el aviso. No se garantiza un plazo hasta que el proyecto establezca capacidad de respuesta.
